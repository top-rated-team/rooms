# Waves 21 and 22, reviewed — and the review that ran out of credit

## Wave 21 — adgrant-as-fork

Three defects found by hand and fixed in `d452007`: a hidden door still had a
page at `/services/<slug>`, AdGrant's new legal pages claimed a LinkedIn
sign-in that address does not offer, and the sign-in panel on adgrant.ai named
top-rated.team (a line I had written the wave before).

The adversarial pass then found four more, all on the new privacy page, and
all confirmed:

**The only contact on either legal page was a link that 301s to a home page.**
`ADGRANT_IDENTITY.contact` was `https://top-rated.team/contact`, and
`server/routes.ts` redirects `/contact` to `/`. So the one link a nonprofit's
data protection officer is given for an erasure request took them off
adgrant.ai and onto another brand's marketing page. It is the address now, the
way top-rated.team's own legal pages have always done it, and
`docs/specs/forking.md` says so too.

**Asking for a person was not disclosed at all.** A room on adgrant.ai carries
the same invite form as any other, and it writes a lead record, stores it,
posts it to a webhook and emails it with the visitor's address as reply-to.
The page had no row for any of that, and named Resend only as the sender of a
room link — conditionally, on a way in that has nothing to do with it. Both
corrected.

**A record outlives the room it came from.** Every generation writes a row
keyed to the person, and it is what enforces three-per-person, so a deletion
cannot reset it. The retention section said a structure is kept with its room
and stopped there. It now says what survives, what is in it — an identifier,
the room, the date — and that asking removes it and the limit with it.

**"Not added to a list" was written of an address we hash and keep.** The
WhatsApp row two lines above discloses exactly that treatment for a chat id.
The email row now does the same, and keeps the true part of the claim: no
mailing list, no other mail.

## Wave 22 — adgrant-room-setup

Read by hand; no adversarial pass (see below). The seven counts are seven
files, each importing on its own, with the combined Editor file beside them.
The gate is real and server-side — `whoAmI(req.headers.cookie)` on
`/api/adgrant/templates/:slug/files`, 401 without a session — rather than a
hidden button. The page states before the sign-in what it is for, in the
owner's own terms: the files are free, the account is so the work can continue
in a room. "Build the files again" is gone rather than mended, which the brief
allowed and which is the right half of that choice. Every campaign in every
file is Paused and nothing writes into a Google Ads account.

One gap, closed here: the brief asked that any new environment variable be
written into `.env.example` with a line saying what breaks without it, because
the owner had asked which variables adgrant.ai needs. The answer is none, and
now that answer is in `.env.example` instead of nowhere.

## The review itself

The wave-21 pass launched 86 agents. **63 of them died on the organisation's
monthly spend limit.** Of 27 claims, 4 were confirmed and 23 are recorded as
"refuted" — but a finding whose three verifiers all failed to start counts as
refuted in that arithmetic, so an unknown share of those 23 were never checked
at all. Four were genuinely confirmed and are fixed above. The rest is not a
clean bill; it is an unfinished one.

No adversarial pass ran over wave 22 for the same reason. It was read by hand.
